# 案件状态分析与报结流程指南

> 本文档分析当前项目案件状态管理的现状、问题，以及前端如何调用接口完成案件报结全流程。

---

## 一、后端是否已实现已报结案件与进行中案件的区别？

### 1.1 结论：部分实现，但存在严重问题

**当前实现情况**：

| 功能点 | 是否实现 | 说明 |
|--------|----------|------|
| 案件状态字段 | ✓ | `case_status` 字段存在 |
| 报结状态(AWAITING) | ✓ | 代码中硬编码使用 |
| 状态枚举定义 | ✗ | `CaseStatus` 枚举缺少 AWAITING、ONGOING |
| 业务操作限制 | ✗ | 没有根据状态限制业务操作 |
| 状态流转控制 | ✓ | 审批通过/拒绝会修改状态 |

### 1.2 核心问题

**问题1：枚举与实际代码不匹配**

[CaseStatus.java](file:///d:/Ai/lawbackend2/src/main/java/com/lawbackend2/lawbackend2/enums/CaseStatus.java) 定义了6个状态：
```java
public enum CaseStatus {
    PENDING("待处理"),
    IN_PROGRESS("进行中"),
    COMPLETED("已完成"),
    CLOSED("已结案"),
    TERMINATED("已终结"),
    ARCHIVED("已归档");
}
```

但代码中实际使用了 **9个状态**（硬编码字符串）：
- `PENDING`、`ONGOING`、`IN_PROGRESS`、`APPROVED`、`AWAITING`、`COMPLETED`、`CLOSED`、`TERMINATED`、`ARCHIVED`

**问题2：缺少 AWAITING 和 ONGOING 枚举值**

代码中大量使用 `"AWAITING"` 和 `"ONGOING"` 字符串，但枚举中没有定义，导致类型不安全。

**问题3：没有业务操作权限控制**

当前代码没有根据案件状态限制业务操作，已报结案件仍然可以执行所有操作。

## 二、案件状态冗余分析与最优方案

### 2.1 当前状态分析

**实际使用的9个状态**：

| 状态 | 使用场景 | 问题 |
|------|----------|------|
| PENDING | 案件刚创建 | 与 IN_PROGRESS 语义重复 |
| ONGOING | 默认状态，进行中 | 与 IN_PROGRESS 完全重复 |
| IN_PROGRESS | 进行中 | 与 ONGOING 完全重复 |
| APPROVED | 已审核通过 | 属于进行中的子状态 |
| AWAITING | 报结申请中 | 缺少枚举定义 |
| COMPLETED | 已完成 | 与 CLOSED 语义相近 |
| CLOSED | 已结案 | 与 COMPLETED 语义相近 |
| TERMINATED | 已终结 | 使用场景不明确 |
| ARCHIVED | 已归档 | 合理 |

### 2.2 冗余问题

```
【冗余组1】进行中的多个状态
├── PENDING      待处理
├── ONGOING      进行中（默认）
├── IN_PROGRESS  进行中（重复）
└── APPROVED     已审核（仍属于进行中）

【冗余组2】已结束的多个状态
├── COMPLETED    已完成
├── CLOSED       已结案（与COMPLETED重复）
└── TERMINATED   已终结（使用场景不明确）
```

### 2.3 最优方案：精简为5个状态

建议将状态精简为以下5个，覆盖所有业务场景：

```
┌─────────────────────────────────────────────────────────────────┐
│                      最优状态方案（5个状态）                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. PENDING       待处理                                         │
│     → 案件刚创建，尚未开始处理                                    │
│                                                                 │
│  2. ONGOING       进行中（合并原ONGOING/IN_PROGRESS/APPROVED）   │
│     → 案件正在正常办理中                                          │
│                                                                 │
│  3. AWAITING      报结中                                         │
│     → 已提交报结申请，等待管理员审核                              │
│                                                                 │
│  4. COMPLETED     已结案（合并原COMPLETED/CLOSED/TERMINATED）    │
│     → 案件流程已结束                                              │
│                                                                 │
│  5. ARCHIVED      已归档                                         │
│     → 案件已归档，仅可查看                                       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.4 状态流转图（最优方案）

```
┌─────────┐         ┌─────────┐         ┌─────────┐         ┌─────────┐         ┌─────────┐
│ PENDING │ ──────→ │ ONGOING │ ──────→ │AWAITING │ ──────→ │COMPLETED│ ──────→ │ARCHIVED │
│  待处理  │         │  进行中  │         │  报结中  │         │  已结案  │         │  已归档  │
└─────────┘         └────┬────┘         └────┬────┘         └─────────┘         └─────────┘
                         │                   │
                         │ 提交报结申请       │ 审批通过
                         │                   │
                         │              ┌────┴────┐
                         │              │ 审批拒绝 │
                         │              │ 回退到  │
                         │              │ ONGOING │
                         │              └─────────┘
                         │
                    ┌────┴────┐
                    │ 撤销审核 │
                    │ 回退到  │
                    │ PENDING │
                    └─────────┘
```

### 2.5 修改建议

**1. 修改 CaseStatus 枚举**

```java
package com.lawbackend2.lawbackend2.enums;

public enum CaseStatus {
    PENDING("待处理"),
    ONGOING("进行中"),
    AWAITING("报结中"),
    COMPLETED("已结案"),
    ARCHIVED("已归档");

    private final String description;

    CaseStatus(String description) {
        this.description = description;
    }

    public String getDescription() {
        return description;
    }

    /**
     * 是否为进行中状态
     */
    public boolean isInProgress() {
        return this == PENDING || this == ONGOING;
    }

    /**
     * 是否为已结束状态
     */
    public boolean isFinished() {
        return this == COMPLETED || this == ARCHIVED;
    }

    /**
     * 是否可以编辑
     */
    public boolean isEditable() {
        return this == PENDING || this == ONGOING;
    }
}
```

**2. 数据库迁移**

```sql
-- 将旧状态映射到新状态
UPDATE tb_bankrupt_case 
SET case_status = 'ONGOING' 
WHERE case_status IN ('IN_PROGRESS', 'APPROVED');

UPDATE tb_bankrupt_case 
SET case_status = 'COMPLETED' 
WHERE case_status IN ('CLOSED', 'TERMINATED');
```

**3. 代码中统一使用枚举**

将所有硬编码字符串替换为枚举：
```java
// 错误示例
bankruptCase.setCaseStatus("ONGOING");

// 正确示例
bankruptCase.setCaseStatus(CaseStatus.ONGOING.name());
```

### 3.2 详细接口调用

#### 步骤1：用户提交报结申请

**接口**：`POST /bankrupt-case/{caseId}/submit-review`

**前端代码**：
```javascript
// 提交报结申请
async function submitCaseForReview(caseId) {
    try {
        const res = await uni.request({
            url: `http://your-domain/api/bankrupt-case/${caseId}/submit-review`,
            method: 'POST',
            header: {
                'Authorization': 'Bearer ' + uni.getStorageSync('token')
            }
        });
        
        if (res.data.code === 200) {
            uni.showToast({
                title: '报结申请已提交',
                icon: 'success'
            });
            // 刷新案件详情
            this.loadCaseDetail(caseId);
        } else {
            uni.showToast({
                title: res.data.message || '提交失败',
                icon: 'none'
            });
        }
    } catch (error) {
        console.error('提交报结申请失败：', error);
        uni.showToast({
            title: '网络请求失败',
            icon: 'none'
        });
    }
}
```

**状态变化**：
- `case_status`: ONGOING → AWAITING
- `review_status`: null → PENDING

// 获取案件详情
async function getCaseDetail(caseId) {
    try {
        const res = await uni.request({
            url: `http://your-domain/api/bankrupt-case/${caseId}`,
            method: 'GET',
            header: {
                'Authorization': 'Bearer ' + uni.getStorageSync('token')

            const caseDetail = res.data.data;

                isAwaiting,
                isPending,
                canReview: isAwaiting && isPending
            };

        return null;
    } catch (error) {
        console.error('获取案件详情失败：', error);
        return null;
    }
}

**状态变化**：

## 四、总结

### 4.1 当前问题

1. **状态枚举不完整**：缺少 AWAITING 和 ONGOING
2. **状态冗余**：9个状态中有4个是重复的
3. **没有业务限制**：已报结案件仍可执行所有操作
4. **硬编码字符串**：代码中大量使用字符串而非枚举

### 4.2 最优方案

将状态精简为5个：
- **PENDING**（待处理）
- **ONGOING**（进行中）
- **AWAITING**（报结中）
- **COMPLETED**（已结案）
- **ARCHIVED**（已归档）

### 4.3 前端调用流程

```
用户提交报结 → 管理员查看待审核 → 管理员审核 → 通过/拒绝
```

| 步骤 | 接口 | 方法 |
|------|------|------|
| 提交报结 | `/bankrupt-case/{id}/submit-review` | POST |
| 查看待审核 | `/bankrupt-case?reviewStatus=PENDING` | GET |
| 查看详情 | `/bankrupt-case/{id}` | GET |
| 审核案件 | `/bankrupt-case/{id}/review` | POST |
| 撤销报结 | `/bankrupt-case/{id}/withdraw-review` | POST |
| 重新提交 | `/bankrupt-case/{id}/resubmit-review` | POST |
