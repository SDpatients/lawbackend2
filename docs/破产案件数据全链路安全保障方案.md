## 三、国密 SM4 存储加密

### 3.1 为什么选择 SM4？

| 对比维度 | AES-256 | SM4 |
|---------|---------|-----|
| 算法来源 | 美国 NIST 标准 | 中国国家标准 GB/T 32907-2016 |
| 合规性 | 无国内合规优势 | **《密码法》明确推荐**，满足政务、司法系统的国产密码要求 |
| 安全性 | 128/192/256 位 | 128 位（等效安全强度） |
| 法律证据力 | 弱 | **强**（国产密码算法在司法举证中更具说服力） |

### 3.2 加密架构

```
原始密钥 (application.yml)
      │
      ▼
HMAC-SHA256 派生 ──── 绑定机器码（Machine Code）
      │
      ▼
16字节派生密钥
      │
      ▼
SM4/CBC/PKCS7Padding 加密
      │
      ▼
Base64 编码存储到数据库
```

### 3.3 实现细节

**核心类**：
- [Sm4Util.java](file:///d:/Ai/lawbackend2/src/main/java/com/lawbackend2/lawbackend2/util/Sm4Util.java) — 底层 SM4/CBC/PKCS7Padding 加密引擎，基于 BouncyCastle 提供者
- [Sm4Encryptor.java](file:///d:/Ai/lawbackend2/src/main/java/com/lawbackend2/lawbackend2/util/Sm4Encryptor.java) — 加密器组件，通过 HMAC-SHA256 将种子密钥与机器码绑定派生出16字节密钥，实现"一机一密"

**关键特性**：

| 特性 | 说明 |
|-----|------|
| 密钥派生 | `HMAC-SHA256(seedKey, machineCode)` → 取前16字节 |
| 加密模式 | SM4/CBC/PKCS7Padding（CBC模式 + PKCS7填充） |
| 初始向量(IV) | 由密钥前16字节派生 |
| 机器码绑定 | 密钥与服务器硬件绑定，即使配置文件泄露，迁移到其他服务器也无法解密 |
| 编码输出 | Base64 字符串，兼容现有 VARCHAR 字段 |

## 四、身份认证与访问控制

### 4.1 认证流程

```
用户登录
    │
    ▼
密码 BCrypt 验证（PasswordUtil.java）
    │
    ├── 失败 → 累加失败计数 → 超5次锁定30分钟
    │
    ▼ 成功
生成 JWT Access Token（HS512签名，50小时有效期）
生成 JWT Refresh Token（30天有效期）
    │
    ▼
Token 返回客户端，存入 Authorization: Bearer <token>
    │
    ▼
每次请求 → JwtAuthenticationFilter 校验 → 解析 userId / permissions
    │
    ▼
设置 SecurityContext → @PreAuthorize 权限注解生效
```

### 4.2 核心组件

| 组件 | 文件 | 功能 |
|-----|------|-----|
| 安全配置 | [SecurityConfig.java](file:///d:/Ai/lawbackend2/src/main/java/com/lawbackend2/lawbackend2/security/SecurityConfig.java) | Spring Security 配置、CORS、密码编码器 |
| JWT 过滤器 | [JwtAuthenticationFilter.java](file:///d:/Ai/lawbackend2/src/main/java/com/lawbackend2/lawbackend2/security/JwtAuthenticationFilter.java) | 每次请求解析 Token，设置认证上下文 |
| Token 工具 | [JwtTokenUtil.java](file:///d:/Ai/lawbackend2/src/main/java/com/lawbackend2/lawbackend2/util/JwtTokenUtil.java) | HS512 签名 Token 生成/校验，权限哈希内置 |
| 密码工具 | [PasswordUtil.java](file:///d:/Ai/lawbackend2/src/main/java/com/lawbackend2/lawbackend2/util/PasswordUtil.java) | BCrypt 加密/验证 |
| 安全工具 | [SecurityUtil.java](file:///d:/Ai/lawbackend2/src/main/java/com/lawbackend2/lawbackend2/util/SecurityUtil.java) | 获取当前登录用户信息 |

### 4.3 多层防护机制

| 防护层 | 机制 | 说明 |
|-------|------|-----|
| 密码强度 | BCrypt 加盐哈希 | 不可逆、抗彩虹表攻击 |
| 防暴力破解 | 登录失败锁定 | 连续5次失败 → 锁定30分钟（可配置） |
| Token 安全 | HS512 签名 + 过期机制 | Access Token 50小时 / Refresh Token 30天 |
| Token 黑名单 | Redis 黑名单 | 登出/修改密码后 Token 立即失效 |
| 权限哈希 | MD5 哈希内置于 Token | 权限变更时自动感知，无需重新登录 |
| 会话管理 | 无状态 STATELESS | 不依赖 Session，杜绝会话固定攻击 |

### 4.4 RBAC 权限模型

```
用户(User) ──N:M──> 角色(Role) ──N:M──> 权限(Permission)
                                                   │
                                          ┌────────┼────────┐
                                          │        │        │
                                      菜单权限   按钮权限   数据权限
```

所有 API 接口通过 `@PreAuthorize("hasAuthority('xxx:xxx:xxx')")` 进行细粒度权限控制，例如：

```java
@PreAuthorize("hasAuthority('system:backup:execute')")  // 仅备份管理员可执行
@PreAuthorize("hasAuthority('system:backup:list')")     // 仅授权用户可查看
@PreAuthorize("hasAuthority('system:backup:delete')")   // 仅授权用户可删除
```

## 七、审计日志与防篡改链

### 7.1 审计日志架构

```
业务方法 (@AuditLog 注解)
    │
    ▼
AuditLogAspect (AOP 切面拦截)
    │
    ├── 记录：操作用户、模块、操作类型、请求参数、IP地址、浏览器、操作系统
    ├── 记录：操作结果（成功/失败）、执行耗时、异常信息
    │
    ▼
tb_audit_log 表写入
    │
    ├── 哈希链：SHA-256(上一条哈希 + 本条数据) → hash_value
    ├── 上链：previous_hash 指向上一条记录
    ├── 数字签名：RSA 私钥签名（可选）
    │
    ▼
数据库触发器保护
    ├── 禁止 DELETE（prevent_audit_log_delete 触发器）
    ├── 禁止 UPDATE（prevent_audit_log_update 触发器）
    └── 篡改检测存储过程（verify_audit_log_integrity）
```

### 7.2 核心组件

| 组件 | 文件 | 功能 |
|-----|------|-----|
| 审计注解 | [AuditLog.java](file:///d:/Ai/lawbackend2/src/main/java/com/lawbackend2/lawbackend2/annotation/AuditLog.java) | 声明式审计标记，支持模块、操作类型、是否记录参数/数据 |
| 审计切面 | [AuditLogAspect.java](file:///d:/Ai/lawbackend2/src/main/java/com/lawbackend2/lawbackend2/aspect/AuditLogAspect.java) | AOP 切面自动采集上下文信息并持久化 |
| 审计实体 | [AuditLog.java](file:///d:/Ai/lawbackend2/src/main/java/com/lawbackend2/lawbackend2/entity/AuditLog.java) | 包含哈希链、数字签名、完整性状态字段 |
| 防篡改触发器 | [audit_log_protection_trigger.sql](file:///d:/Ai/lawbackend2/sql/audit_log_protection_trigger.sql) | 数据库层面防止审计日志被删除或修改 |
| 完整性验证 | `verify_audit_log_integrity` 存储过程 | 逐条验证哈希链完整性，输出篡改率 |

### 7.3 审计字段说明

| 字段 | 说明 |
|-----|------|
| `hash_value` | 当前记录的 SHA-256 哈希值，链式关联上一条 |
| `previous_hash` | 上一条记录的哈希值，形成不可逆的哈希链 |
| `digital_signature` | RSA 私钥数字签名（可选） |
| `integrity_status` | 完整性状态：VERIFIED / TAMPERED / PENDING |
| `chain_sequence` | 哈希链序号，用于完整性验证 |

### 7.4 审计日志防篡改机制

```sql
-- 禁止删除审计日志
CREATE TRIGGER prevent_audit_log_delete
BEFORE DELETE ON tb_audit_log
FOR EACH ROW
BEGIN
    SIGNAL SQLSTATE '45000'
    SET MESSAGE_TEXT = '禁止删除审计日志：审计日志记录不可删除，以确保合规审查的完整性';
END;

-- 禁止修改审计日志（仅允许完整性状态从VERIFIED变为TAMPERED）
CREATE TRIGGER prevent_audit_log_update
BEFORE UPDATE ON tb_audit_log
FOR EACH ROW
BEGIN
    IF NOT (OLD.integrity_status = 'VERIFIED' AND NEW.integrity_status = 'TAMPERED') THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '禁止修改审计日志：审计日志记录不可修改，以确保合规审查的完整性';
    END IF;
END;
```

**安全声明**：
- 审计日志采用**哈希链表**结构，任何一条记录被篡改都会导致后续所有记录的哈希值不匹配
- **数据库触发器**从数据库层面杜绝直接 SQL 删除/修改审计日志
- 提供**定期完整性验证**存储过程，可自动检测篡改并标记

## 十五、总结

- **系统可用性**：定时备份 + 接口限流 + 许可证管理
