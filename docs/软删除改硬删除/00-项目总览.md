# 软删除改硬删除 - 项目总览

## 背景说明

当前项目使用软删除（通过 `isDeleted` 字段）来标记数据删除状态，但存在以下问题：
- 删除后再次添加相同案号的案件时报错
- 软删除数据积累导致数据库膨胀
- 增加查询复杂度

**解决方案**：将所有软删除改为硬删除（Hibernate `delete()` 方法），数据通过备份机制保证安全。

## 修改原则

### 1. 实体层修改
- ✅ **删除** `isDeleted` 字段（如果该实体不需要软删除）
- ✅ **保留** 其他业务字段不变
- ✅ 如果实体继承 `BaseEntity` 或 `LibBaseEntity`，需要考虑是否改为继承普通基类

### 2. Repository层修改
- ✅ **删除** 所有包含 `isDeleted = false` 条件的查询方法
- ✅ **修改** 自定义 `deleteByCaseId` 方法为硬删除
- ✅ **保留** 正常的 `findById`、`findAll` 等方法

### 3. Service层修改
- ✅ **修改** 所有软删除方法为硬删除
- ✅ 将 `setIsDeleted(true)` + `save()` 改为直接 `delete(entity)`
- ✅ **保留** 事务注解 `@Transactional`

### 4. Controller层修改
- ✅ 删除相关的删除API通常不需要修改
- ✅ 如果有特殊的软删除恢复逻辑，需要删除

### 5. 数据库字段考虑
- ⚠️ **建议保留** `is_deleted` 字段暂不删除，待完全验证后再清理
- ⚠️ 可创建注释说明该字段已废弃

## 特别注意事项

### 1. BankruptCaseServiceImpl - 核心模块
这是最关键的文件，`deleteCase` 方法需要特别注意：

**当前实现（软删除）**：
```java
// 设置为已删除
bankruptCase.setIsDeleted(true);
bankruptCaseRepository.save(bankruptCase);
```

**修改后（硬删除）**：
```java
// 直接硬删除主实体
bankruptCaseRepository.delete(bankruptCase);
```

同时，`createCase` 方法中的恢复逻辑需要简化：
```java
// 删除此段代码
if (existing.isPresent()) {
    if (!existing.getIsDeleted()) {
        throw new BusinessException("案号已存在");
    }
    // 恢复逻辑...（删除）
}

// 直接创建新记录
BankruptCase bankruptCase = new BankruptCase();
// ...
bankruptCaseRepository.save(bankruptCase);
```

### 2. BaseEntity 和 LibBaseEntity
这两个基类被多个实体继承，修改需要谨慎：
- 如果大多数实体都需要硬删除，建议保留基类但标记 `isDeleted` 为废弃
- 如果所有实体都硬删除，可以删除基类中的 `isDeleted` 字段

### 3. Repository 查询方法
所有包含 `isDeleted = false` 的 `@Query` 方法都需要修改：
- **修改前**：`@Query("SELECT c FROM BankruptCase c WHERE c.isDeleted = false")`
- **修改后**：`@Query("SELECT c FROM BankruptCase c")` 或直接使用 `findAll()`

4. ✅ 所有查询功能正常工作
5. ✅ 关联删除功能正常
