## 整体架构说明

### 技术栈

**后端技术**:
- Spring Boot 2.6.13
- WebSocket + STOMP协议
- SockJS作为降级方案
- JWT Token认证

**前端技术**:
- SockJS-client (WebSocket降级库)
- STOMP.js (STOMP协议客户端)
- REST API (HTTP请求)

### 通信方式

前端与后端通信采用两种方式：

1. **WebSocket实时通信** - 用于实时消息推送
   - 新消息通知
   - 消息已读通知
   - 消息撤回通知
   - 正在输入状态

2. **REST API** - 用于业务操作
   - 发送消息
   - 获取历史消息
   - 会话管理
   - 文件上传下载

### 后端配置信息

**WebSocket端点**: `/ws` (包含context-path: `/api/v1/ws`)
**协议**: HTTP + SockJS + STOMP
**认证方式**: JWT Token (通过连接头传递)
**消息路由**:
- 应用消息: `/app/**`
- 广播主题: `/topic/**`
- 用户队列: `/user/queue/**`

## 前端实现流程

### 阶段一: 项目准备

#### 步骤1: 引入依赖库

**方式1: CDN引入**
- 引入sockjs-client库
- 引入stompjs库
- 建议使用多个CDN源作为备份

**方式2: npm安装**
- 安装sockjs-client包
- 安装stompjs包
- 在代码中import引入

**注意事项**:
- 确保库加载顺序正确
- 检查库版本兼容性
- 处理CDN加载失败的情况

#### 步骤2: 配置基础URL

**需要配置的URL**:
- WebSocket连接URL
- REST API基础URL
- 文件上传URL
- 文件下载URL

**URL格式说明**:
- WebSocket使用HTTP协议，不是WS协议
- 必须包含完整的context-path
- 开发环境和生产环境使用不同配置

---

### 阶段二: 用户认证

#### 步骤3: 获取JWT Token

**流程**:
1. 用户登录获取Token
2. 将Token存储到本地存储
3. 在后续请求中携带Token

**Token使用位置**:
- REST API请求头: `Authorization: Bearer {token}`
- WebSocket连接头: `Authorization: Bearer {token}`

**注意事项**:
- Token需要包含"Bearer "前缀
- Token过期需要自动刷新
- 不要在前端硬编码Token

---

### 阶段三: WebSocket连接建立

#### 步骤4: 初始化WebSocket连接

**连接流程**:
1. 创建SockJS连接对象
2. 使用STOMP包装SockJS
3. 配置连接头信息
4. 建立连接并处理回调

**连接成功后操作**:
1. 标记连接状态为已连接
2. 订阅个人消息队列
3. 订阅正在输入状态主题
4. 初始化心跳检测

**连接失败处理**:
1. 记录错误日志
2. 显示连接失败提示
3. 实现自动重连机制
4. 限制重连次数和间隔

#### 步骤5: 订阅消息队列

**需要订阅的主题**:
1. `/user/queue/notifications` - 个人通知队列
2. `/topic/chat/typing` - 正在输入状态

**订阅时机**:
- 在连接成功回调中订阅
- 确保订阅路径正确
- 处理订阅失败情况

**消息处理流程**:
1. 接收到消息后解析JSON
2. 根据消息类型分发处理
3. 更新UI显示
4. 触发相应业务逻辑

### 阶段四: 聊天界面初始化

#### 步骤6: 获取会话列表

**流程**:
1. 调用获取会话列表API
2. 分别获取置顶和未置顶会话
3. 合并并排序显示
4. 显示未读消息数

**API调用**:
- 获取置顶会话: `/chat/conversations/pinned`
- 获取未置顶会话: `/chat/conversations/unpinned`
- 获取总未读数: `/chat/unread/count`

**数据处理**:
- 过滤已删除的会话
- 按最后消息时间排序
- 显示最后一条消息预览
- 显示未读消息数

#### 步骤7: 进入聊天会话

**流程**:
1. 用户点击会话列表项
2. 调用获取或创建会话API
3. 获取会话历史消息
4. 标记会话消息为已读
5. 更新未读消息数

**API调用**:
- 获取或创建会话: `/chat/conversation`
- 获取会话消息: `/chat/messages`
- 标记会话已读: `/chat/conversations/read`

**注意事项**:
- 消息按时间倒序加载
- 实现分页加载历史消息
- 滚动到最新消息位置

---

### 阶段五: 消息发送与接收

#### 步骤8: 发送文本消息

**流程**:
1. 用户输入消息内容
2. 验证消息内容不为空
3. 调用发送消息API
4. 将消息添加到本地列表
5. 清空输入框

**API调用**:
- 发送消息: `/chat/messages` (POST)

**消息格式**:
- receiverId: 接收者ID (数字类型)
- messageType: "TEXT"
- content: 消息内容

**错误处理**:
- 检查连接状态
- 验证消息格式
- 处理发送失败情况
- 显示错误提示

#### 步骤9: 接收实时消息

**流程**:
1. WebSocket接收到新消息通知
2. 解析通知内容
3. 判断是否为当前会话
4. 更新消息列表
5. 滚动到最新消息

**通知类型处理**:
- NEW_MESSAGE: 新消息通知
- MESSAGE_READ: 消息已读通知
- MESSAGE_RECALLED: 消息撤回通知

**UI更新**:
- 如果是当前会话，直接添加消息
- 如果不是当前会话，更新未读数
- 显示消息提示或通知

### 阶段六: 文件消息处理

#### 步骤10: 文件上传

**流程**:
1. 用户选择文件
2. 验证文件类型和大小
3. 调用文件上传API
4. 获取文件ID和URL
5. 发送文件消息

**API调用**:
- 文件上传: `/file/upload` (POST)
- 发送文件消息: `/chat/messages` (POST)

**文件类型判断**:
- 图片类型: IMAGE消息
- 其他类型: FILE消息

**注意事项**:
- 文件大小限制
- 上传进度显示
- 上传失败处理

---

### 阶段七: 消息操作

#### 步骤11: 标记消息已读

**触发时机**:
- 用户打开会话时
- 用户滚动到消息时

**实现方式**:
- 方式1: 调用标记会话已读API
- 方式2: 通过WebSocket发送已读状态

**API调用**:
- 标记消息已读: `/chat/messages/read` (PUT)
- 标记会话已读: `/chat/conversations/read` (PUT)

#### 步骤12: 撤回消息

**流程**:
1. 用户长按或右键点击消息
2. 检查是否在2分钟内
3. 调用撤回消息API
4. 更新本地消息状态
5. 显示撤回提示

**API调用**:
- 撤回消息: `/chat/messages/recall` (PUT)

**限制条件**:
- 只能撤回自己的消息
- 时间限制2分钟
- 已撤回的消息不能再次撤回

#### 步骤13: 删除消息

**流程**:
1. 用户选择删除消息
2. 调用删除消息API
3. 从本地列表移除消息
4. 更新会话最后消息

**API调用**:
- 删除消息: `/chat/messages` (DELETE)

**注意事项**:
- 只能删除自己的消息
- 删除是软删除
- 对方不受影响

#### 步骤14: 置顶/取消置顶会话

**流程**:
1. 用户选择置顶或取消置顶
2. 调用置顶API
3. 更新本地会话列表
4. 重新排序显示

**API调用**:
- 置顶/取消置顶: `/chat/conversations/pin` (PUT)

#### 步骤15: 删除会话

**流程**:
1. 用户确认删除会话
2. 调用删除会话API
3. 从本地列表移除会话
4. 清空消息列表

**API调用**:
- 删除会话: `/chat/conversations` (DELETE)

**注意事项**:
- 删除会话只影响自己
- 对方会话不受影响
- 消息记录仍然保留

### 阶段九: 连接管理

#### 步骤16: 断开连接

**触发时机**:
- 用户退出登录
- 页面卸载
- Token过期

**断开流程**:
1. 取消所有订阅
2. 断开WebSocket连接
3. 清理本地状态
4. 停止心跳检测

#### 步骤17: 自动重连

**重连策略**:
1. 检测连接断开
2. 延迟一段时间后重连
3. 限制最大重连次数
4. 重连成功后重新订阅

**注意事项**:
- 避免频繁重连
- 显示重连状态提示
- 重连失败后的处理

## WebSocket通信流程

### 连接建立流程

1. **创建SockJS连接**
   - 使用HTTP协议创建连接
   - 传入完整的WebSocket端点URL
   - 包含context-path

2. **包装为STOMP客户端**
   - 使用Stomp.over()包装
   - 配置调试日志选项
   - 设置心跳参数

3. **建立连接**
   - 传入连接头信息
   - 包含JWT Token
   - 处理成功和失败回调

### 消息发送流程

1. **发送聊天消息**
   - 目标地址: `/app/chat/send`
   - 消息体: JSON格式
   - 包含receiverId、messageType、content

2. **发送正在输入状态**
   - 目标地址: `/app/chat/typing/{conversationId}`
   - 消息体: 空对象
   - 实时通知对方

3. **发送已读状态**
   - 目标地址: `/app/chat/read/{messageId}`
   - 消息体: 空对象
   - 通知消息已读

### 消息接收流程

1. **订阅个人通知队列**
   - 订阅地址: `/user/queue/notifications`
   - 接收个人专属消息
   - 处理各种通知类型

2. **订阅正在输入状态**
   - 订阅地址: `/topic/chat/typing`
   - 接收广播消息
   - 显示正在输入提示

3. **处理不同类型通知**
   - NEW_MESSAGE: 新消息通知
   - MESSAGE_READ: 消息已读通知
   - MESSAGE_RECALLED: 消息撤回通知

## 易错点总结

### 1. 协议混淆错误

**错误现象**: 使用ws://协议连接WebSocket

**正确做法**: 使用http://协议
- SockJS使用HTTP协议
- 不是原生WebSocket的ws://协议
- 生产环境使用https://

**影响**: 连接失败，错误代码1006

### 2. URL路径错误

**错误现象**:
- 使用`/ws`而不是`/api/v1/ws`
- 缺少context-path
- 路径拼写错误

**正确做法**:
- 完整路径: `/api/v1/ws`
- 包含context-path
- 确认后端配置

**影响**: 连接404错误

### 3. 订阅路径错误

**错误现象**:
- 使用`/queue/notifications`
- 使用`/topic/notifications`

**正确做法**:
- 个人队列: `/user/queue/notifications`
- `/user`前缀会被替换为用户ID

**影响**: 收不到个人消息

### 4. Token格式错误

**错误现象**:
- Token缺少"Bearer "前缀
- Token过期未刷新
- Token硬编码在前端

**正确做法**:
- 格式: `Authorization: Bearer {token}`
- 自动刷新过期Token
- 从安全存储获取

**影响**: 认证失败，401错误

### 5. 消息格式错误

**错误现象**:
- receiverId使用字符串类型
- messageType大小写错误
- 缺少必填字段

**正确做法**:
- receiverId必须是数字
- messageType使用大写: TEXT/IMAGE/FILE
- 根据消息类型提供相应字段

**影响**: 消息发送失败，400错误

### 6. 连接状态未检查

**错误现象**:
- 未连接就发送消息
- 连接断开后未重连
- 未处理连接失败

**正确做法**:
- 发送前检查连接状态
- 实现自动重连机制
- 显示连接状态提示

**影响**: 消息丢失，用户体验差

### 7. 消息类型混淆

**错误现象**:
- TEXT消息包含fileId
- FILE消息缺少fileId
- 消息类型大小写错误

**正确做法**:
- TEXT: 只提供content
- IMAGE/FILE/VOICE/VIDEO: 提供fileId
- 统一使用大写

**影响**: 消息显示异常

### 8. 时间限制忽略

**错误现象**:
- 超过2分钟仍尝试撤回
- 撤回自己不能撤回的消息
- 删除自己不能删除的消息

**正确做法**:
- 检查消息创建时间
- 验证消息发送者
- 显示错误提示

**影响**: 操作失败，用户体验差

### 9. 未读消息数未更新

**错误现象**:
- 标记已读后未更新UI
- 收到新消息未增加未读数
- 切换会话未更新未读数

**正确做法**:
- 标记已读后立即更新UI
- 收到新消息增加未读数
- 进入会话清空未读数

**影响**: 未读数不准确

### 10. 文件上传失败处理

**错误现象**:
- 上传失败仍发送消息
- 文件类型验证不严格
- 文件大小限制未处理

**正确做法**:
- 上传成功后再发送消息
- 验证文件类型和大小
- 显示上传进度和错误

**影响**: 消息发送失败，文件丢失

### 11. CDN库加载失败

**错误现象**:
- SockJS或Stomp未定义
- 页面报错无法运行
- 没有备用CDN

**正确做法**:
- 使用多个CDN源
- 检测库是否加载成功
- 提供npm安装方案

**影响**: 页面无法运行

### 12. 内存泄漏

**错误现象**:
- 页面卸载未断开连接
- 未取消订阅
- 事件监听器未清理

**正确做法**:
- 页面卸载时断开连接
- 取消所有订阅
- 清理事件监听器

**影响**: 性能下降，内存占用高

### 13. 消息顺序错误

**错误现象**:
- 消息显示顺序混乱
- 时间戳未正确处理
- 分页加载顺序错误

**正确做法**:
- 按时间戳排序
- 历史消息倒序加载
- 新消息追加到末尾

**影响**: 消息显示混乱

### 14. 撤回消息处理错误

**错误现象**:
- 收到撤回通知未移除消息
- 撤回消息仍显示内容
- 未显示撤回提示

**正确做法**:
- 收到撤回通知移除消息
- 显示"消息已撤回"提示
- 更新消息状态

**影响**: 消息显示异常

### 15. 正在输入状态处理错误

**错误现象**:
- 正在输入提示不消失
- 多个用户同时输入显示错误
- 未处理离开输入状态

**正确做法**:
- 设置定时器清除提示
- 区分不同用户的输入状态
- 发送消息后清除提示

**影响**: 用户体验差

## 关键注意事项

### 安全注意事项

1. **Token管理**
   - 不要在前端硬编码Token
   - Token过期后自动刷新
   - 使用HTTPS传输Token
   - Token存储在安全位置

2. **连接安全**
   - 生产环境使用HTTPS
   - 验证服务器证书
   - 限制跨域来源
