# 1月12日待办API汇总

## 1. 接口概述

待办事项管理API提供了一套完整的待办事项管理功能，包括待办事项的创建、查询、更新、删除、状态管理、分配、搜索和统计等功能。该API适用于法律业务管理系统中的任务跟踪、工作提醒和协作场景。

### 主要功能模块

- **待办事项管理**：创建、编辑、删除待办事项
- **状态管理**：更新待办状态、完成待办事项
- **任务分配**：将待办事项分配给指定用户
- **查询检索**：支持多条件搜索、列表查询、待处理/过期查询
- **统计分析**：统计待处理、已完成、过期待办数量
- **批量操作**：批量删除待办事项

### 技术特性

- 基于RESTful架构设计
- 支持分页查询
- 统一的响应格式
- WebSocket实时通知（创建和完成待办时）
- 事务管理保证数据一致性

| 状态码 | 说明 |

### 2.5 PUT /todo/{todoId}/complete - 完成待办事项

**功能说明**：将待办事项标记为已完成，自动记录完成时间，并发送WebSocket通知

**特殊处理逻辑**

1. 检查待办事项是否存在
2. 检查待办事项是否已完成，如果已完成则抛出异常
3. 将状态更新为COMPLETED
4. 自动设置completedTime为当前时间
5. 发送WebSocket实时通知给相关用户

**请求参数**

| 参数名 | 类型 | 位置 | 必填 | 说明 |
|--------|------|------|------|------|
| todoId | Long | Path | 是 | 待办事项ID |

**请求示例**

```http
PUT /todo/123/complete
```

**响应格式**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 123,
    "title": "完成案件材料整理",
    "status": "COMPLETED",
    "completedTime": "2024-01-11T16:30:00",
    "updateTime": "2024-01-11T16:30:00"
  }
}
```

**错误响应示例**

```json
{
  "code": 400,
  "message": "待办事项已完成",
  "data": null
}
```

**状态码**

| 状态码 | 说明 |
|--------|------|
| 200 | 完成成功 |
| 400 | 待办事项已完成 |
| 404 | 待办事项不存在 |
| 500 | 服务器内部错误 |

### 2.8 GET /todo/search - 搜索待办事项

**功能说明**：根据类型、状态、优先级等多条件搜索待办事项，支持分页

**查询参数**

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | Long | 是 | 用户ID |
| type | String | 否 | 待办类型 |
| status | String | 否 | 待办状态 |
| priority | String | 否 | 优先级 |
| pageNum | Integer | 否 | 页码，默认0 |
| pageSize | Integer | 否 | 每页大小，默认10 |

**支持的搜索条件**

- 按类型搜索：type参数
- 按状态搜索：status参数
- 按优先级搜索：priority参数
- 支持多条件组合搜索

**分页参数**

| 参数名 | 说明 | 默认值 |

| pageNum | 页码，从0开始 | 0 |
| pageSize | 每页大小 | 10 |

**请求示例**

```http
GET /todo/search?userId=1001&type=案件处理&status=PENDING&priority=HIGH&pageNum=0&pageSize=10
```

**响应格式**

```json
{

        "userId": 1001,
        "title": "完成案件材料整理",
        "type": "案件处理",
        "status": "PENDING",
        "priority": "HIGH",

        "createTime": "2024-01-10T10:00:00"

    ],

      "pageNumber": 0,
      "pageSize": 10

    "totalPages": 3,

    "last": false,

  "data": null

```

**状态码**

| 状态码 | 说明 |
|--------|------|
| 200 | 批量删除成功 |
| 400 | 请求参数错误 |
| 500 | 服务器内部错误 |

---

## 3. 通用说明

### 3.1 统一的错误响应格式

所有接口在发生错误时返回统一的错误响应格式：

```json
{
  "code": 400,
  "message": "错误描述信息",
  "data": null
}
```

### 3.2 错误码说明

| 错误码 | 说明 | 处理建议 |
|--------|------|----------|
| 200 | 请求成功 | 正常处理 |
| 400 | 请求参数错误 | 检查请求参数格式和必填项 |
| 401 | 未授权 | 检查认证信息 |
| 403 | 无权限 | 检查用户权限 |
| 404 | 资源不存在 | 检查资源ID是否正确 |
| 500 | 服务器内部错误 | 联系技术支持 |

### 3.3 认证方式及请求头格式

**认证方式**

- 使用JWT Token认证
- Token在用户登录后获取

**请求头格式**

```http
Authorization: Bearer {token}
Content-Type: application/json
```

**示例**

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Content-Type: application/json
```

### 3.4 接口调用频率限制

**频率限制规则**

- 每个用户每分钟最多调用100次API
- 超过限制将返回429状态码

**频率限制响应**

```json
{
  "code": 429,
  "message": "请求过于频繁，请稍后再试",
  "data": null
}
```

**建议**

- 合理使用分页功能减少请求次数
- 对于列表数据，建议使用WebSocket实时更新而非轮询
