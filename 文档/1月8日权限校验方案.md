# 后端系统登录校验与权限控制方案

## 一、系统架构概述

本项目采用前后端分离架构，后端基于Spring Boot + Spring Security + JWT实现认证与授权机制。系统采用RBAC（基于角色的访问控制）模型，实现了完整的用户认证、授权、权限管理功能。

## 二、登录校验机制

### 1. 登录流程

```
前端 → 后端登录接口 → 用户名密码验证 → 短信验证码验证（可选） → 生成JWT Token → 前端存储Token
```

### 2. 登录凭证验证

#### 2.1 用户名/密码验证

- **密码加密**：使用BCrypt算法对密码进行单向哈希加密，确保密码安全存储
- **验证流程**：
  - 检查用户名是否存在
  - 验证密码是否匹配
  - 检查账号状态是否为`ACTIVE`
  - 检查账号是否被锁定

#### 2.2 短信验证码验证（可选）

- **触发条件**：当请求中包含有效的4-6位数字验证码时，触发短信验证码验证
- **验证逻辑**：调用`SmsService.verifySmsCode()`方法验证验证码的有效性和过期时间
- **验证码类型**：登录验证码类型为`LOGIN`（代码中常量定义为"1"）

#### 2.3 登录失败处理

- **失败记录**：每次登录失败都会记录失败信息到`tb_login_fail`表
- **失败次数限制**：连续登录失败次数超过配置的阈值（默认5次），账号将被锁定
- **锁定时长**：锁定时间为配置的时长（默认30分钟）
- **失败类型**：区分账号不存在、密码错误、验证码错误等不同失败类型

### 3. JWT Token生成与管理

#### 3.1 Token生成

- **生成工具**：使用`JwtTokenUtil`类生成JWT Token
- **Token内容**：
  - Header：包含算法类型（HS512）和Token类型（JWT）
  - Payload：包含用户ID、用户名、签发时间、过期时间
  - Signature：使用配置的密钥进行签名
- **过期时间**：可在`application.yml`中配置，默认值可通过`@Value("${jwt.expiration}")`注入

#### 3.2 Token存储

- **数据库存储**：生成的Token会存储在`tb_token`表中，记录Token状态、过期时间、IP地址、设备信息等
- **状态管理**：Token状态包括`ACTIVE`（活跃）和`INACTIVE`（失效）
- **刷新机制**：支持Token刷新，刷新时旧Token失效，生成新Token

#### 3.3 Token验证

- **验证时机**：每次请求到达后端时，通过`JwtAuthenticationFilter`进行验证
- **验证内容**：
  - Token格式是否正确
  - Token是否过期
  - Token签名是否有效
- **验证流程**：
  1. 从请求头`Authorization`中提取Token
  2. 验证Token有效性
  3. 从Token中提取用户信息
  4. 创建认证对象并存储到SecurityContext中

### 4. 登出机制

- **接口调用**：前端调用`/auth/logout`接口
- **处理逻辑**：
  - 从请求头中提取Token
  - 更新数据库中Token状态为`INACTIVE`
  - 设置Token失效时间

## 三、权限校验流程

### 1. RBAC模型设计

#### 1.1 实体关系

```
User → UserRole → Role → RolePermission → Permission
```

#### 1.2 实体定义

- **User**：用户信息，包含用户名、密码、状态等
- **Role**：角色信息，包含角色编码、角色名称等
- **Permission**：权限信息，包含权限编码、权限名称、权限类型等

#### 1.3 权限类型

权限类型通过`perm_type`字段定义，用于区分不同类型的权限：
- 菜单权限：控制前端菜单的显示
- 功能权限：控制接口的访问

### 2. 权限校验流程

#### 2.1 请求拦截

- **拦截器**：`JwtAuthenticationFilter`负责拦截所有请求
- **放行路径**：
  - `/auth/**`：认证相关接口
  - `/swagger-ui/**`：Swagger文档
  - `/api-docs/**`：API文档
  - 其他公开接口

#### 2.2 身份验证

- **Token验证**：验证请求携带的Token是否有效
- **用户信息提取**：从Token中提取用户ID和用户名
- **认证对象创建**：创建`UsernamePasswordAuthenticationToken`对象，包含用户ID和默认角色`ROLE_USER`
- **认证状态设置**：将认证对象存储到`SecurityContextHolder`中

#### 2.3 权限判断

- **当前实现**：目前系统仅实现了基本的认证功能，所有认证通过的用户都被赋予`ROLE_USER`角色
- **权限扩展点**：
  - 可在`JwtAuthenticationFilter`中从数据库获取用户实际角色和权限
  - 可在`SecurityConfig`中配置基于角色或权限的访问控制规则
  - 可使用`@PreAuthorize`注解在接口方法上进行细粒度权限控制

## 四、前端相关接口

### 1. 登录接口

#### 1.1 接口信息

- **请求路径**：`/auth/login`
- **请求方法**：`POST`
- **请求类型**：`application/json`

#### 1.2 请求参数

| 参数名 | 类型 | 必填 | 描述 |
|--------|------|------|------|
| username | String | 是 | 用户名 |
| password | String | 是 | 密码 |
| smsCode | String | 否 | 短信验证码（4-6位数字） |

#### 1.3 响应数据格式

```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "userId": 1,
    "username": "admin",
    "realName": "管理员",
    "token": "eyJhbGciOiJIUzUxMiJ9...",
    "permissions": ["user:read", "user:write"]
  }
}
```

#### 1.4 关键字段说明

- **token**：JWT认证令牌，后续请求需携带此token
- **permissions**：用户拥有的权限列表，用于前端权限控制

### 2. 登出接口

#### 2.1 接口信息

- **请求路径**：`/auth/logout`
- **请求方法**：`POST`
- **请求头**：`Authorization: Bearer {token}`

#### 2.2 响应数据格式

```json
{
  "code": 200,
  "message": "成功",
  "data": null
}
```

### 3. Token刷新接口

#### 3.1 接口信息

- **请求路径**：`/auth/refresh-token`
- **请求方法**：`POST`
- **请求参数**：`token`（当前有效的JWT Token）

#### 3.2 响应数据格式

```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "userId": 1,
    "username": "admin",
    "realName": "管理员",
    "token": "eyJhbGciOiJIUzUxMiJ9...",
    "permissions": ["user:read", "user:write"]
  }
}
```

## 五、安全配置

### 1. 安全配置文件

- **配置类**：`SecurityConfig.java`
- **主要配置**：
  - 禁用CSRF保护
  - 禁用CORS
  - 设置会话管理为`STATELESS`（无状态）
  - 配置认证失败处理类
  - 配置权限规则
  - 添加JWT过滤器

### 2. 密码加密

- **加密算法**：BCrypt
- **配置方式**：通过`@Bean`注解注册`BCryptPasswordEncoder`实例

### 3. 认证失败处理

- **处理类**：`JwtAuthenticationEntryPoint`
- **处理逻辑**：当认证失败时，返回统一的错误响应，包含错误码和错误信息

## 六、代码结构与关键组件

### 1. 核心组件

| 组件类型 | 类名 | 职责 |
|----------|------|------|
| 安全配置 | SecurityConfig | Spring Security核心配置 |
| JWT过滤器 | JwtAuthenticationFilter | Token验证与认证 |
| JWT工具 | JwtTokenUtil | Token生成与解析 |
| 用户服务 | UserServiceImpl | 用户登录、注册、信息管理 |
| 密码工具 | PasswordUtil | 密码加密与验证 |
| 认证控制器 | AuthController | 处理认证相关请求 |

### 2. 数据传输对象（DTO）

| DTO类型 | 类名 | 用途 |
|---------|------|------|
| 请求DTO | UserLoginRequest | 登录请求参数封装 |
| 响应DTO | UserLoginResponse | 登录响应数据封装 |
| 请求DTO | AssignRolePermissionsRequest | 角色权限分配请求 |
| 请求DTO | AssignUserRolesRequest | 用户角色分配请求 |

### 3. 配置文件

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| jwt.secret | JWT签名密钥 | 配置文件中定义 |
| jwt.expiration | Token过期时间（毫秒） | 配置文件中定义 |
| jwt.header | Token请求头 | Authorization |
| jwt.prefix | Token前缀 | Bearer |
| login.max-fail-count | 最大登录失败次数 | 5 |
| login.lock-minutes | 账号锁定分钟数 | 30 |

## 七、优化建议

### 1. 权限控制优化

- **细粒度权限**：实现基于角色和权限的细粒度访问控制
- **动态权限**：支持运行时动态调整用户权限
- **权限缓存**：将用户权限信息缓存，减少数据库查询

### 2. Token管理优化

- **双Token机制**：实现Access Token和Refresh Token分离
- **Token黑名单**：维护Token黑名单，支持强制失效
- **定期清理**：定期清理过期和无效Token

### 3. 安全增强

- **增加验证码**：登录页面添加图形验证码，防止暴力破解
- **IP限制**：对异常登录IP进行限制
- **多因素认证**：支持短信验证码、邮箱验证码等多因素认证
- **安全审计**：完善登录日志和操作日志记录

## 八、总结

本系统实现了完整的登录校验和权限控制机制，采用JWT作为认证令牌，实现了无状态认证。系统基于RBAC模型设计，具备良好的扩展性和可维护性。前端在登录过程中需要调用的主要接口包括登录接口、登出接口和Token刷新接口，通过这些接口与后端进行交互，实现用户认证和授权。

系统目前已经实现了基本的认证功能，后续可以根据业务需求进一步扩展细粒度的权限控制、动态权限管理、多因素认证等高级功能，以提高系统的安全性和可用性。
